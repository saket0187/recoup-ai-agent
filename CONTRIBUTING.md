# Contributing

Thanks for looking. This project has a few unusual constraints, and a change
that breaks one of them will fail CI even if it works.

## Getting set up

```bash
npm install
npm run db:migrate
npm run check
```

No API keys, no database server, no native compilation.

Retraining the uplift model additionally needs Python 3.11+, and nothing else
does. The trained model is a committed JSON file, so the demo, the tests and the
measurement all run without it.

```bash
npm run ml:setup     # virtualenv in ml/
npm run ml:check     # ruff, pyright, pytest, golden-vector verification
```

## Before you open a pull request

`npm run check` must pass. It runs, in order:

1. `check:secrets`, scans everything that would be committed for credentials
   and personal data, using this project's own detector
2. `format:check`, Prettier
3. `typecheck`, TypeScript, strict, with `noUncheckedIndexedAccess`
4. `lint`, ESLint, including the determinism bans
5. `test`, the full suite

If you touch anything under `ml/`, `npm run ml:check` must pass as well. CI runs
it on Python 3.11 and 3.13.

A pre-commit hook runs the formatter and the secret scan on staged files, and
`ruff format` plus `ruff check --fix` on staged Python. It is installed
automatically by `npm install`.

## The constraints that will fail your change

These are enforced by lint or by tests, not by review.

- **No `Date.now()`, `new Date()`, `Math.random()` or `randomUUID()`.** Take a
  `Clock` and a seeded `Rng`. A given seed must replay byte-identically.
- **Money is integer paise** behind the branded `Paise` type. Never `number`.
- **`decisions.propensity` is never defaulted.** It is the one column that makes
  off-policy evaluation possible later, and it cannot be backfilled.
- **Historical retrieval goes through `temporalCutoff`.** A query that can see
  an outcome from the future voids every metric downstream of it.
- **The engine must not import the simulator.** It consumes gateway events and
  the database, exactly as it would in production.
- **TypeScript owns feature encoding.** The Python trainer composes the feature
  blocks the exporter emits; it never computes them. Re-implementing an encoder
  on the Python side is how train/serve skew gets in.
- **A model and its golden vectors change together.** `fixtures/uplift-model.json`
  and `fixtures/uplift-golden.json` are regenerated by the same command and must
  be committed in the same change. CI checks that the model still reproduces them.
- **The agent may not regress below the incumbent schedule.** It may beat it and
  it may deliberately stop, but the fixed-schedule floor is not optional.
- **No personal data in the repository.** Fixtures are synthetic. The secret
  scanner enforces this; do not weaken a pattern to get past it.

## Tests

Tests live in `tests/`, named after the module. Two suites carry meta-tests that
will fail if you add a rule without a test:

- `policy.test.ts` needs one test per policy rule ID
- `stop-gate.test.ts` needs one test per stop condition

Prefer a test that would have caught a real bug over one that restates the
implementation.

## Reporting numbers

Simulation constants are assumptions, not measurements. If you change one,
update `docs/simulation-assumptions.md` in the same commit and say what it does to
the sensitivity analysis. Never tune a constant until a result looks good.
